# 말씀통독 체크 (bible-check)

휴대폰에서 매일 성경읽기를 체크하는 웹앱(PWA). 기록은 **각자의 폰에만** 저장된다 — 서버·로그인 없음.

> 설계 결정의 이유는 볼트 노트 `01_ME/2026-10-03_PLAN_성경읽기체크앱_설계.md` 참고.

## 원칙

1. **기록은 폰 밖으로 나가지 않는다.** 서버는 앱 파일만 전달한다. 분석·추적 스크립트 금지.
2. **추궁하지 않는다.** 밀린 날짜 수를 보여주지 않는다. "오늘 말씀"과 "다음 읽을 곳"만.
3. **읽기표와 앱은 분리한다.** 읽기표는 데이터 파일 하나. 다음 통독은 파일만 바꾼다.
4. **탭 한 번.** 매일 하는 동작은 앱 열기 → 체크, 끝.

## 대상

- 선한길교회 팀/소그룹 5~20명, 아이폰·갤럭시 혼재
- 배포: 카톡으로 링크 공유 → "홈 화면에 추가"

## 데이터

### 읽기표 (`plans/<id>.json`, 앱에 포함)

분량은 문자열이 아니라 **책·장 범위**로 저장한다 — 장 단위 체크·본문 링크·(나중의) 66권 지도·읽기표 생성기가 모두 이 구조 위에서 돈다.

```json
{
  "id": "goodway-2026h2",
  "title": "선한길 6개월 말씀통독",
  "start": "2026-07-06",
  "end": "2026-12-25",
  "days": [
    { "n": 1,  "date": "2026-07-06", "ranges": [{ "book": "MAT", "from": 1, "to": 7 }] },
    { "n": 18, "date": "2026-07-23", "ranges": [{ "book": "ACT", "from": 28, "to": 28 },
                                                { "book": "ROM", "from": 1,  "to": 6 }] }
  ]
}
```

- 원본: 볼트 `01_ME/faith/reading-plan.md` (173일, 25주). 주차는 `start`부터 7일 단위로 계산.
- 책 코드는 표준 3글자(OSIS/USFM 계열), 한글 이름·장 수는 `books.json` 한 곳에서 관리.
- 화면 표기는 `ranges`에서 생성 (예: "사도행전 28장-로마서 6장"). 시편은 "편"으로 표기.
- 변환 후 검증: 173일, 날짜 연속, 66권 전 장이 빠짐·중복 없이 한 번씩.

### 교회·설교 (`data/church.json`, `data/sermons.json`)

- `church.json`: 교회 이름 + 설교 유튜브 재생목록 ID. 다른 교회에서 쓰면 이 파일만 바꾼다 (없으면 설교 탭이 숨는다).
- `sermons.json`: 재생목록의 최근 영상 15개. GitHub Actions(`.github/workflows/sermons.yml`)가 일요일 밤·월요일엔 20분마다 새 설교를 확인해(리눅스, 가벼움) 있을 때만 맥에서 썸네일을 읽고 커밋한다 → 올라온 뒤 보통 20~40분 안에 앱에 반영. 앱은 다시 열 때마다 목록을 새로 받는다. 급하면 Actions 탭 → "설교 목록 갱신" → Run workflow, 또는 `npm run sermons`.
- 설교 제목·본문·시리즈는 유튜브 설명란에 없고 **썸네일 그림에만** 있다 → 맥 문자 인식(`scripts/ocr.swift`, Vision)으로 읽는다. 그래서 Actions도 맥 환경(macos-latest, 공개 저장소 무료)에서 돈다. 구절은 맞춤법 교정을 끈 결과로 읽는다(교정이 '-'를 지움).
- 잘못 읽힌 제목·구절은 GitHub에서 `data/sermons.json`을 바로 고치면 된다 — 한 번 읽은 영상은 다시 읽지 않으므로 고친 값이 유지된다.
- 재생목록을 통째로 퍼오면(videoseries) "볼 수 없습니다"가 뜬다(팟캐스트 지정 재생목록). 그래서 영상 하나씩 띄운다.
- 서비스워커는 `sermons.json`만 네트워크 먼저 → 매주 새 목록이 앱 업데이트 없이 반영된다.

### QT (`data/church.json`의 `qt`, `data/qt.json`)

- 「매일성경」(성서유니온, 일반판 `QT1`) 날짜별 **제목·본문 구절만** 보여 준다. 본문·해설 글은 저작권이 있어 앱에 넣지 않고 "본문·해설 보기"로 성서유니온 그날 페이지에 연결.
- `qt.json`은 GitHub Actions(`.github/workflows/qt.yml`)가 매일 새벽 4시 성서유니온 '오늘의 묵상'에서 받는다. 사이트가 2주쯤 앞까지 열어 두므로 앱엔 늘 2주 치가 있다. 손으로: `npm run qt`.
- QT 체크는 통독과 따로: 같은 저장소에 `planId: 'qt'`, `day: 20261101` 꼴로 저장 → 내보내기 백업에 같이 들어간다. 통독표를 바꾸거나 통독이 끝나도 QT 기록은 그대로.
- 판(일반·순·고학년 등)을 바꾸려면 `church.json`의 `qt.edition`만 바꾼다.

### 개인 기록 (폰 안, IndexedDB)

나중의 Supabase 동기화를 위해 **기록 = 하루 1건의 레코드** (고유 ID + 수정 시각).

```json
{ "id": "uuid", "planId": "goodway-2026h2", "day": 18,
  "chapters": { "ACT.28": "2026-07-23", "ROM.1": "2026-07-24" },
  "readOn": "2026-07-24", "note": "", "updatedAt": "2026-07-24T07:12:00.000Z", "deleted": false }
```

- `chapters` = 읽은 장 → **그 장을 실제로 체크한 날짜**. 그날 `ranges`의 장이 전부 들어오면 그날 완료.
- `readOn` = 마지막으로 읽은 날. `note` = 선택 한 줄 묵상.
- 쓰기는 `store.update()` 한 곳 — 한 트랜잭션 안에서 **DB의 최신 기록에 변경을 적용**한다(앱이 두 곳에 열려 있어도 서로 덮어쓰지 않음). 다른 탭엔 BroadcastChannel로 알림.
- 가져오기: 전부 검사 → 한 트랜잭션에 반영(전부 아니면 전무). 같은 날은 **장 합집합**(먼저 읽은 날짜 유지), 묵상은 최근 쪽. 설정은 `catchupMode`만.
- IndexedDB 버전을 올릴 땐 `onupgradeneeded`에 `if (e.oldVersion < 2)` 단계를 추가(기존 기록 유지).

## 화면

0. **처음 열 때** — ① 환영(무엇을 하는 앱인지·기록은 이 폰에만) → ② 이름(필수, 폰에만 저장 — 오늘 화면 인사, 설정에서 변경) → ③ 어디까지 읽으셨어요?(통독 도중 기록 없이 처음 연 사람만: '오늘부터' = 이어가기 방식 '오늘 말씀부터'로 시작 / '이미 읽고 있었어요' = 마지막 읽은 날 골라 한 번에 채우기 / 백업 가져오기). 이름은 백업에 담지 않는다
1. **오늘** — 날짜·주차, 오늘 말씀 카드
   - `[다 읽었어요]` 한 번 = 그날 전체 체크 / "장별로 체크"를 펼치면 장 단위("4/6장 읽음")
   - 체크하면 한 줄 묵상 입력란이 나타남(선택). 입력은 화면을 다시 그리지 않고 저장
   - 이번 주 7칸(탭 → 하루 상세), 누적 기록("이번 달 N일 · 지금까지 N장")
2. **따라잡기** — 지난 날이 남아 있을 때만. 처음엔 방식 선택 카드, 이후엔 한 줄("지난 말씀은 ○○ · 바꾸기")
   - ① 밀린 것부터: '이어 읽기' 카드. 방금 끝낸 카드는 잠시 그대로 둔다(연타 방지·묵상 입력)
   - ② 오늘 말씀부터: 지난 날은 전체 표에서
   - ③ 나눠 얹기: 덤 칩. 하루 덤은 그날 분량을 넘지 않음(넘치면 마감 약속 대신 "이어 읽을 수 있어요")
   - 밀린 날짜 수·주별 "n/7"·스트릭은 보여주지 않는다. 기간이 끝나면 이어 읽기 하나만
3. **전체 표** — 주차 카드 25개(현재 주로 스크롤), 다 읽은 주 ✓ / 일부 "N일 읽음". 행 탭 → 하루 상세
4. **하루 상세 시트** — 장별 체크, 다 읽었어요, 묵상, **여기까지 읽었어요**(첫날~이 날 빈 날을 계획 날짜로 채움 — 이미 읽고 있던 사람의 시작점). 안드로이드 뒤로가기로 닫힘
5. **설정** — 이름, 화면(밝기 자동/밝게/어둡게 · 글자 크기 보통/크게/아주 크게 — 이 폰에만, localStorage), 이어가기 방식, 내보내기/가져오기, 홈 화면 추가 안내(아이폰 사파리·크롬·삼성 인터넷·카톡 인앱 각각)

안내: 카톡 등 인앱 브라우저에서 열리면 "다른 브라우저로 열기"를 홈·설정에 띄운다(인앱 기록은 따로 저장되므로). 아이폰은 사파리와 홈 화면 앱의 기록이 분리 → 추가 전 내보내기 안내.

## 디자인

색·글자 크기는 `style.css` 맨 위 토큰(`:root`)에서만 정한다. 디자인을 바꿀 땐 그 블록(밝은 화면·어두운 화면 두 벌)만 고친다. 글씨 색은 배경 대비 4.5:1 이상, 글자 크기는 `calc(Npx * var(--fs))`로 써서 설정 배율을 따른다.

